# Phase 0 Beginner Guide (Java Backend)

This guide is for a first-time backend student.
Goal: finish Phase 0 foundations before real business features.

## What you already did

1. Java version is aligned to 25.
2. Database env and profiles are configured.
3. Package folders exist.

Great start. Now we create the first class skeletons.

## Final objective of this guide

At the end, you should have:

1. Global error format and global exception handler.
2. Security and CORS base config.
3. JWT service interface.
4. Minimal auth DTOs + generic page DTO.
5. Minimal domain entities and role enum.
6. 3 repositories.
7. 4 controllers with simple test endpoints.

## Step 1: Create cross-cutting classes

Create these files first.

1. `src/main/java/com/pfa/backend/infrastructure/exception/ApiError.java`
2. `src/main/java/com/pfa/backend/infrastructure/exception/GlobalExceptionHandler.java`
3. `src/main/java/com/pfa/backend/infrastructure/security/SecurityConfig.java`
4. `src/main/java/com/pfa/backend/config/CorsConfig.java`
5. `src/main/java/com/pfa/backend/infrastructure/security/JwtService.java`

### What each one does

1. `ApiError`: one JSON format for all errors.
2. `GlobalExceptionHandler`: catches exceptions and returns `ApiError`.
3. `SecurityConfig`: central security rules.
4. `CorsConfig`: allows frontend calls.
5. `JwtService`: token contract only (interface for now).

1. `src/main/java/com/pfa/backend/application/dto/auth/LoginRequest.java`

1. DTOs are request/response only.
2. DTOs should not contain business logic.

## Step 6: Build and run checks

From `backend/` run:

```powershell
mvn -q clean compile
```

If compile passes, run app:

```powershell
mvn spring-boot:run
```

Test endpoints:

1. `http://localhost:8080/api/health`
2. `http://localhost:8080/api/v1/auth/ping`
3. `http://localhost:8080/api/v1/students/ping`
4. `http://localhost:8080/api/v1/recruiters/ping`
5. `http://localhost:8080/api/v1/admin/ping`

## Step 7: Architecture rules (important)

Keep these rules from day one.

1. Controller calls Service only.
2. Service handles business logic.
3. Repository handles database access only.
4. Controller returns DTOs, not JPA entities.
5. Errors go through `GlobalExceptionHandler`.

## Common beginner mistakes to avoid

1. Putting business logic directly inside controllers.
2. Returning entity classes directly in API responses.
3. Mixing DTO and entity responsibilities.
4. Creating many features before compiling small increments.
5. Ignoring package boundaries.

## Recommended work rhythm

1. Create 2 to 4 files.
2. Compile.
3. Fix errors.
4. Continue.

Small steps are faster and safer than creating all files at once.

## Phase 1 Starter Plan (recommended order)

Use this order to move from skeleton to real backend features.

### Step 1: Finalize domain relationships

Focus on JPA relationships and ownership consistency.

1. Confirm relation directions (`@OneToOne`, `@ManyToOne`, `@OneToMany`) and owning sides.
2. Add `mappedBy` where needed for bidirectional links.
3. Add cascade/fetch only where needed; keep defaults simple.
4. Rebuild after each small batch:

```powershell
mvn -q clean compile
```

### Step 2: Add validation rules

Put bean validation on input DTOs first.

1. Add `@NotBlank`, `@Email`, `@Size`, etc. on request DTO fields.
2. Use `@Valid` in controller methods.
3. Extend `GlobalExceptionHandler` to return field-level errors for validation failures.
4. Compile and test invalid input payloads.

### Step 3: Build authentication flow

Implement real register/login behavior.

1. Create `AuthService` interface + implementation.
2. Implement `JwtServiceImpl` from current `JwtService` interface.
3. Add password hashing with `PasswordEncoder`.
4. Add endpoints:
	- `POST /api/v1/auth/register`
	- `POST /api/v1/auth/login`
5. Return DTOs only (never entity objects directly).

### Step 4: Add first business feature

Start with one simple business slice, for example job offers.

1. Add service methods and DTOs for creating/listing offers.
2. Keep controller thin: controller -> service -> repository.
3. Add one pagination endpoint using `PageResponse<T>`.
4. Test with sample data.

### Step 5: Add tests before scaling

1. Add controller/service tests for auth success/failure.
2. Add at least one test for the first business endpoint.
3. Keep test data minimal and deterministic.

### Phase 1 done checklist

1. Register/login works with hashed passwords and JWT.
2. Validation errors return a consistent `ApiError` structure.
3. At least one real business endpoint is functional.
4. Build and tests pass.
